# 管理页说明

[English](admin.en.md)

管理员登录后，顶栏是 **题目 / 数据 / 题库 / 手册**。普通用户是 **题目 / 成绩 / 提交记录**。管理员自己做题仍走「题目」，能看见全部已导入题（含未发布）。普通登录只能看见已发布的题，打开后「测试」跑示例、「提交」跑隐藏测例；同一场面试在时限内可以重复提交，以最好一次 AC 为准。

导入后默认未发布。要给考生做：题库 → 发布。

不要在网页上改别人密码、不删账号。

## 题目

管理员：列表含未发布，标题旁有「未发布」。普通用户：列表只有已发布。测试不计成绩；提交才跑隐藏测例。

## 数据

| 入口 | 你做什么 | 看到什么 |
| --- | --- | --- |
| 每题统计 | 打开列表；点一行 | 每题提交数、AC 数、通过率；再进入该题最近提交 |
| 用户总览 | 打开列表；点一行 | 该用户总提交、总通过率、各语言提交与通过率；再进入该用户最近提交 |

通过率 = `AC` 次数 / 全部正式提交。没有提交显示为「—」，不是 0%。日志最多 300 条。点行可看源码。普通用户看不到别人的源码。

## 题库

三种入口都会改评测机上的题目。同一道题不要又用网页写、又用 Git 改。

文件内容（`meta.yaml` 等怎么写）见仓库 [`docs/problems.md`](problems.md)。本页只说按钮怎么点、点完怎么办。

### 远程同步

**做：** 本机已经把题目推到 GitHub 之后，点「从 Git 同步」。只改了评测机磁盘上的题目、没有推送：点「只重新加载磁盘」。

| 页面上出现 | 下一步 |
| --- | --- |
| 已拉取并加载 N 题 | 到「题目」确认新题在列表里 |
| 远程没有新提交 | 不用再点；若本机还没 push，先 push 再同步 |
| 提示需要在评测机上重启 | 到评测机重启服务，见 [server.md](server.md) |
| 红字报错 | 按报错处理（连不上 GitHub、权限、冲突），不要反复猛点 |

### 本机导入

**做：** 两个选择框用一个。选本机 `problems/某题名` 文件夹，或直接选一个 `.zip`（不用先解压）。同名题目要换成这次上传的，勾选「覆盖评测机上的同名题目」。浏览器不好选文件夹时，可在 Windows 上先跑 `.\scripts\pack-problems.ps1 -Slug 某题名`，再用它打印的 zip。

| 页面上出现 | 下一步 |
| --- | --- |
| 已写入某题名 | 到「题目」打开该题，看题面和编辑器是否正常 |
| 缺少某个文件 / 不是有效 zip | 补齐四个必需文件，或换一个包，再选一次 |
| 题目已存在 | 勾上覆盖后再选，或换一个目录名 |

### 发布

**做：** 导入完成后到「发布」。未发布的题只有管理员能在「题目」里打开。点「发布」后，普通登录才能看见并提交。点「撤回」则考生列表里消失。

| 页面上出现 | 下一步 |
| --- | --- |
| 已发布某题 | 用普通账号刷新「题目」应能看到 |
| 还没有导入题目 | 先本机导入 zip |

### 按文件上传

**做：** 填写题目目录名。新题一次选齐 `meta.yaml`、`statement.md`、`signature.yaml`、`tests.jsonl`。已有题可以只选要改的那几份。点「写入目录」。需要空函数模板时，成功后再点「生成 starter」。

| 页面上出现 | 下一步 |
| --- | --- |
| 已写入，并出现「生成 starter」 | 到「题目」打开该题；需要模板再点生成 |
| 还缺某某文件 | 新题必须四份都选上，再点写入 |
| slug 不一致 / 文件无效 | 改文件或改目录名，与 [`docs/problems.md`](problems.md) 对齐后再传 |
| 已生成 starter | 打开该题，换语言看编辑器是否有空函数 |

上传失败时，题目列表里不会多出一道缺文件的坏题。不要把隐藏测例贴进聊天或网页文本框，只传文件。

## 提交变慢时

测试和正式提交忙的时候：提交会排队，测试按钮会多转一会儿。等结果即可。

要改评测机上同时能编/跑几份：在评测机上改，见 [server.md](server.md)「评测并发」。不要改仓库里的代码来当配置。
